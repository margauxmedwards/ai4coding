[01] · BEGINNER

Your first ten minutes

For people who can read basic code and are new to AI coding tools. Finish with one small, verified change. No custom agent or skill is needed to begin.

  • Open a disposable practice folder in VS Code. Use the Python exercise linked below; Python 3 is the only runtime dependency.
  • Open the Chat view, sign in to your enabled coding assistant, and note the tool and selected model. Setup varies by account; use your organisation’s approved access.
  • Open the function and test file. Attach them with the chat’s file/context control, or name their exact paths.
  • Ask for an explanation first. For the edit, use a mode that permits file changes and inspect any command approval before accepting it.
  • Run the checks, review the diff in Source Control, and keep or undo the change.

Download average.py · Download test_average.py

First task: make an empty list return 0.0 while preserving the existing average for non-empty lists.

[02] · BEGINNER

Six words, one workflow

Model

The system generating the answer: for example, GPT, Claude or Gemini.

Tool

The application giving the model access to files and commands: for example, Copilot or Claude Code.

Agent

A model working through a task using tools, with permissions and constraints.

Context

The information available for this task: prompt, files, instructions and tool results.

Token

A chunk of text or other encoded input/output. Usage and billing depend on the model and product.

Skill

A reusable task recipe that a compatible agent can load when relevant.

A file being in your repository does not prove the agent read it. Ask it to identify the relevant files and check its references.

[05] · BEGINNER

Give it a task it can finish

Goal

State the behaviour you want, in plain language.

Context

Name the files, environment and known error.

Evidence

Specify a command or example that establishes success.

Boundary

Say what may change and what needs another decision.

Read average.py and test_average.py. Explain why empty input fails.
Propose the smallest fix before editing.

After I accept the approach, make average([]) return 0.0.
Preserve the result for non-empty numeric lists.
Run: python3 -m unittest -v
Do not change the expected results or add dependencies.
Report the diff and tests passed, failed or not run.
Keep changes local; ask before pushing or publishing.

[06] · BEGINNER

Watch a failure become evidence

Illustrative walkthrough. The downloadable exercise starts with this bug:

def average(values):
    return sum(values) / len(values)

# average([2, 4, 6]) -> 4.0
# average([])        -> ZeroDivisionError

1 · Reproduce

Run the tests before editing. Confirm the empty-input case fails for the expected reason.

2 · Change

Add a guard for an empty list. Keep the established non-empty behaviour.

3 · Verify

Run the same tests again: empty input, a normal list and negative values.

4 · Review

Read the small diff. Check that tests were not weakened just to make them pass.

# Expected minimal fix
if not values:
    return 0.0
return sum(values) / len(values)
“Done” is a claim. The test output and the diff are evidence you can inspect.

[07] · BEGINNER

Ask → plan → act → verify

Ask

Use questions to understand unfamiliar code or missing requirements.

Plan

For multi-file or uncertain work, agree on scope and checks before editing.

Act

Let the agent make the agreed change and run relevant commands.

Verify

Check behaviour, the diff and the reported results before accepting.

These are workflow stages; exact mode names differ by tool. A tiny, well-defined edit may combine planning and action. Larger changes benefit from explicit checkpoints.

If it loops on the same failure, stop and ask for the failing command, exact error and a revised hypothesis. Supply missing evidence before trying a larger model.

[08] · BEGINNER

Know how to keep or undo it

  • Start from a saved checkpoint or a disposable copy. A branch alone does not save uncommitted work.
  • Review each changed file. Use your editor’s diff view to compare additions and removals.
  • Run the known example and an edge case yourself. Passing tests only cover the cases those tests exercise.
  • To undo, use the editor’s revert control for the specific agent change after checking the diff. Preserve your own edits.
  • Keep credentials and private datasets out of the exercise. Understand what a requested terminal command will do.
For a real robot or dataset, begin with simulation or a small copied sample and define the additional checks before scaling up.

[09] · BEGINNER

Save a workflow after it works

Project instructions hold general conventions. A skill captures a recurring task. Ask the agent to draft a skill from the verified workflow, then review it.

# .github/skills/validate-change/SKILL.md
---
name: validate-change
description: Check a small Python change and report evidence. Use after edits.
---
1. Read the task and inspect the diff.
2. Run the project's documented test command.
3. Check the requested behaviour and one edge case.
4. Report files changed, commands, results and checks not run.
5. Do not push or publish without an explicit request.
6. Propose reusable lessons; review them before saving.

The name and description help the tool discover the skill. Invoke it explicitly for the first trial and verify that it was loaded. Locations and optional features vary across compatible agents.

Sources: VS Code skills

Skills do not learn automatically. Save a lesson only after confirming that it is correct and reusable.

[10] · BEGINNER

Try it, check it, repeat it

  • Complete the empty-input exercise using one model.
  • Explain the final diff and show the passing test output.
  • Try a second model from the same starting files if you want a comparison.
  • Save one useful project instruction or reusable skill.
  • Move to the advanced talk when you want to run larger, repeatable workflows.
